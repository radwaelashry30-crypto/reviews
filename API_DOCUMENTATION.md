# API Documentation

Base URL (local dev): `http://localhost:8000`
API prefix: `/api/v1`
Interactive docs: `http://localhost:8000/docs` (Swagger UI) · `http://localhost:8000/openapi.json` (OpenAPI schema)

## Standard response envelope

Every endpoint returns:

```json
{ "success": true, "data": { }, "meta": { "api_version": "v1", "model_version": null, "request_id": "..." } }
```

Errors:

```json
{ "success": false, "error": { "code": "MODEL_NOT_AVAILABLE", "message": "...", "details": {} }, "meta": { "request_id": "..." } }
```

| HTTP status | Meaning |
|---|---|
| 200 | Successful read / prediction |
| 400 | Invalid business input (e.g. translation requested but disabled) |
| 404 | Unknown resource |
| 422 | Schema-validation failure (Pydantic) |
| 500 | Unexpected internal error (stack trace never exposed) |
| 503 | A requested model artifact is not available |

## Endpoints

### `GET /api/v1/health`
```bash
curl http://localhost:8000/api/v1/health
```

### `GET /api/v1/models/status`
Reports per-artifact status (`available`/`unavailable`/`invalid`/`loading_failed`), device, and safe metadata (no absolute paths).

### `GET /api/v1/models/info`
Model manifest, notebook-reported metrics, label mapping, limitations statement.

### `POST /api/v1/sentiment/predict`
```bash
curl -X POST http://localhost:8000/api/v1/sentiment/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "The product arrived early and works perfectly.", "model_name": "bert"}'
```
```json
{
  "success": true,
  "data": {
    "label": "Positive", "class_id": 1,
    "probability_positive": 0.9988, "probability_negative": 0.0012,
    "confidence": 0.9988, "model_name": "bert",
    "source_language": "en", "translated": false,
    "cleaned_text": "The product arrived early and works perfectly."
  },
  "meta": { "api_version": "v1", "model_version": "bert", "request_id": "..." }
}
```

React usage:
```ts
import { predictSentiment } from "./api/sentimentApi";
const result = await predictSentiment({ text, model_name: "bert", source_language: "en", translate: false });
```

### `POST /api/v1/sentiment/predict-batch`
```json
{ "items": [{"id": "review-1", "text": "Excellent product."}, {"id": "review-2", "text": "The item arrived broken."}], "model_name": "bert" }
```
Returns `{ "results": [...], "n_items": 2 }`; each result item includes the original `id`. Max batch size: `MAX_BATCH_SIZE` (default 64).

## Model availability behavior

Optional artifacts (BERT, CNN2D, RFM) are loaded once at startup. If one is missing, the API still starts; that model's endpoints return `503 MODEL_NOT_AVAILABLE` instead of crashing the whole app. Check `/api/v1/models/status` to see what's loaded.

## Batch / rate limitations

- Single review text: max `MAX_REVIEW_LENGTH` characters (default 2000).
- Batch predictions: max `MAX_BATCH_SIZE` items per request (default 64).
- No rate limiting is enforced by default (local/academic deployment); add a reverse-proxy rate limiter for production use.

## CORS

Configured via `FRONTEND_ORIGINS` in `.env` (default: `http://localhost:3000`, `http://localhost:5173`). Add your deployed frontend's origin there — do not use `*` in production.

## Label mapping

`{"Negative": 0, "Positive": 1}` — reviews with 1-2 stars are Negative, 4-5 stars are Positive. 3-star (neutral) reviews are excluded from the classification task entirely; they are not predicted or scored.
